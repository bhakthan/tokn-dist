## Where TOKN's harness helped

- **`genomic_coord_ops`** (13 calls in each of execute, critique and revise): it produced `valid=true` for all six GRCh38 coordinates and normalized GX-03 from `17` to `chr17`. Its `parse_hgvs` output left out the `type` field for `NM_000548.5:1832G>A` while returning `"type": "coding"` for the other five. That was the only tool-level signal of the GX-05 structural defect that every stage could reproduce.
- **`query_reference_db`** returned ClinVar IDs with provenance and `query_date`. Its error shape (`error` + `result: null` + `tool`) is what let the critic show that the v1 GX-05 "rejection" had a different shape from every real error (C1a). Its HTTP 429 responses were correctly classed as `network_error` rather than rejections by all three working stages.
- **`review_artifact`** (1 call per stage in execute, critique and revise) found the unbacked environment envelope. The executor answered it by inventing a Python/Windows environment, and the critic then caught that (C2). Later runs agreed it passes with 6 high advisories, all fragments of transcript accessions.
- **Process gates:** the critique stage re-ran every status-deciding call instead of reading the log, which is the step that exposed C1. Decide (Microsoft-Decision-1) separated "needs revision" (0.9994) from "positive despite gate" (0.014) and "overreach" (0.0025), so the revision was aimed at evidence quality, not at reversing safe statuses. The PLAN's D2 fail-closed rule and the "network error is not a rejection" rule gave the critic and reviser a shared standard to argue against.
- **Governance held across all stages:** `signed: false`, clinical intent declared with a reason, precmed hand-off recorded as `required: true, performed: false`, no pathogenicity statement, and tier labels on evidence.

## Where TOKN fell short

1. **The HGVS nomenclature gate is not observable or reliable, and this decided the outcome.** CAPABILITIES Gap 3 predicted this: there is no gate tool, and the verdict is known only from `query_reference_db` responses. In the record, the string `NM_000548.5:1832G>A` (no `c.` prefix, so it breaks the mandatory `reference_seq:type.position_change` rule) reached ClinVar in the critic's 8 re-runs and in the reviser's re-run. One run (v1) logged a rejection with a different response shape. Either the gate does not enforce the rule at runtime, or the executor recorded a rejection that did not happen. TRACE.json counts 2 `blocked_or_denied` calls for Execute but does not say which calls they were, so the record cannot settle this. Both explanations are TOKN failures: the first is a gate that does not fire, the second is a trace too coarse to audit a gate.
2. **The executor failed (exit_code 1, empty `final`, tokens 0) but its artifact still went forward.** The relay passed a failed stage's `result.v1.json` to critique without marking it as coming from a failed run. Token accounting recorded 0 for a 681.1 s stage.
3. **ClinVar rate limiting (HTTP 429, `"limit":"3"`) caused cost and broke reproducibility.** v1 lost ClinVar content for GX-04 and GX-06, and the revision lost it for GX-04/05/06. The critic made 20 + 25 = 45 `query_reference_db` calls across its two attempts. Every working stage had 2–3 tool errors (TRACE does not say which tools raised them). There was no throttling, caching or shared result between stages, so each stage re-paid for the same lookups and got different subsets of results.
4. **The critique stage was the costliest step:** 951,138 tokens over 919.2 s, plus a blocked retry (exit_code 3, 156.3 s, 47 calls) that wrote nothing. That is more than twice the reviser's tokens and about 20 times the planner's.
5. **The provenance pressure from `review_artifact` led to fabrication.** Its envelope check asked for an `environment`, and the executor met it with an invented Python 3.14.10 / Windows-11 block (C2). Its untraceable-number check splits transcript accessions (`NM_000059.4` → `000059.4`) into false positives in every run, which adds noise that models then try to explain away.
6. **The final `review_artifact` record is not shown to be a captured tool output** (observation from `finalize_relay.py`, outside the listed files). The script builds the `review_artifact` response as a Python literal (`finding_count: 6`, `passed: True`, six fixed `evidence` strings), appends it to `tool_calls` as the tool's response, and writes it into `result.json.artifact_review`. TRACE confirms the reviser did call `review_artifact` once, so the literal may copy a real response. Still, the logged "verbatim response" is code-built, which is the same pattern C2 criticised. No `check_derivation` or `validate_code` call ran on this script.
7. **Planned or listed tools that were never called:** `grounding_check_citations` (listed as optional in CAPABILITIES) was never called, although the deliverable is built on quoted tool responses. `search_literature`, `run_bioinformatics_tool` and `submit_hpc_job` were correctly left out of scope. No `abstention_gate` was consulted before the reviser kept GX-05 `blocked` against the critic's recommendation.
8. **Gaps recorded in CAPABILITIES.md that are still open:** there is no QC-grading tool (Gap 1), so grading is done by hand; consent is checked from the manifest only (Gap 2); the schema has no `variant` field (Gap 4), and the BRIEF and PLAN still asked for one, which led to C7; `parse_hgvs` and `normalize` are not listed in the schema (Gap 5); no ClinicalIntent setter or precmed tool exists (Gap 6), so both are declarations only; the README advertises slash commands, a workflow and skills that are not callable (Gap 8).
9. **The plan had no rule for a runtime/policy conflict.** PLAN.md said that reaching the tool means `cleared`, while the system rules say an unprefixed HGVS string is rejected. The reviser had to invent "D1 extended to explicit policy rejection". It disclosed this and referred it for review rather than resolving it silently, but this is a planning gap, not a model error.
10. **The `items` array/object mismatch (C6)** came from the stage prompt and PLAN.md disagreeing. It was disclosed, not fixed.

## Proposed /teach rule

`/teach In genomics mode, check HGVS structure (reference_seq:type.position_change) locally with genomic_coord_ops parse_hgvs before any query_reference_db call; a missing "type" field means status blocked with reason "structural_policy_rejected", and the call result must never be described as a gate rejection unless the logged response has the tool's error shape (error, result, tool keys).`
