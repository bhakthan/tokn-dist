# Example: Run TOKN Inside an NVIDIA OpenShell Sandbox

> "Give the agent a model, a working directory and nothing else — and keep the API key out of its reach."

[NVIDIA OpenShell](https://github.com/NVIDIA/OpenShell) runs agents in sandboxes. It decides which hosts a sandbox may reach, splits the filesystem into read-only and writable parts, runs the agent as a non-root user, and keeps credentials out of the sandbox. Inside, the agent sees only a placeholder such as `openshell:resolve:env:ANTHROPIC_API_KEY`. OpenShell's proxy swaps in the real key on the wire, and only for the hosts and binaries the provider profile names.

`tokn openshell` makes TOKN a first-class OpenShell workload. It generates the three artifacts OpenShell needs from your existing TOKN configuration, then launches the sandbox with one command.

| Capability | What you see |
|---|---|
| Dependency preflight | `tokn openshell preflight` lists every missing tool at once, with install commands. |
| Provider profile | `tokn openshell profile` emits a `tokn-*` profile that binds the `tokn` binary, with the right auth header. |
| Egress policy | `tokn openshell policy` emits an enforcing policy: your model host only, for `tokn` only. |
| BYOC image | `tokn openshell dockerfile` emits a non-root Dockerfile with self-update switched off. |
| One-command launch | `tokn openshell up` builds, imports, creates the provider and launches. `--dry-run` previews. |
| Sandbox awareness | Inside, TOKN refuses self-update and treats a denied host as policy. `tokn doctor` reports the sandbox. |

The three `*.example*` files in this folder were generated by `tokn openshell` itself, so you can read exactly what it produces before running anything.

## 0. What you need

| Requirement | Why | Check |
|---|---|---|
| TOKN v0.3.58 or newer | `tokn openshell` ships in this version. | `tokn version` |
| Community tier (no trial) | The OpenShell integration is not gated by a license feature. | `tokn openshell --help` |
| Linux, or WSL 2 on Windows | OpenShell's gateway runs on Linux. macOS: see OpenShell's own install notes. | `uname -s` |
| OpenShell CLI and a running gateway | TOKN drives the `openshell` CLI; it does not reimplement it. | `openshell --version` |
| Docker or Podman | Builds the sandbox image. Use the same engine as your gateway. | `docker --version` |
| A Linux TOKN binary | Goes into the image. Download `tokn_linux_amd64` or `tokn_linux_arm64` from the releases page. | `file tokn_linux_amd64` |
| An LLM provider key **in your host environment** | OpenShell reads it from there when the provider is created. | `echo ${ANTHROPIC_API_KEY:+set}` |

`tokn openshell preflight` checks the CLI, the gateway and the container engine together, and prints the install command for anything missing. Install OpenShell with:

```bash
curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh
```

**What leaves your machine:** Generating artifacts (steps 1 to 3) is local and makes no network calls. `tokn openshell up` builds an image locally and talks to your local OpenShell gateway. Once the agent runs, it reaches **only** the hosts in the policy — your model provider — and sends your prompts and tool results there. Your API key is read by OpenShell from your host environment; it is never written to a file in this folder, passed on a command line, or copied into the sandbox.

## 1. Check dependencies

```bash
cd examples/openshell
tokn openshell preflight
```

On Windows, run the remaining steps inside WSL:

```powershell
wsl --cd "$PWD\examples\openshell"
```

## 2. See how your provider maps to OpenShell

```bash
tokn openshell profile --list
```

OpenShell injects a credential only for a binary its profile names. Its own example profiles bind clients like `curl`, not TOKN, so TOKN generates its own `tokn-*` profiles that bind `/usr/local/bin/tokn`. Compare yours with [profile.example.yaml](profile.example.yaml) (Anthropic):

- `credentials[].env_vars` names the variable OpenShell reads on the host — never its value.
- `header_name: x-api-key` is Anthropic's header. Azure OpenAI uses `api-key`; OpenAI-compatible servers use a bearer token.
- `binaries` is the line that makes injection work for TOKN.

## 3. Review the policy and image

```bash
tokn openshell policy --out policy.yaml
tokn openshell dockerfile --binary tokn_linux_amd64 --out Dockerfile
```

Compare with [policy.example.yaml](policy.example.yaml) and [Dockerfile.example](Dockerfile.example):

- **Policy.** `enforcement: enforce` (OpenShell's default is audit). Egress is limited to the model host and bound to the `tokn` binary. Rules are inherited by child processes, so anything allowed for `tokn` is also reachable by tools it spawns. System paths are read-only; `/sandbox` and `/tmp` are writable.
- **Image.** It runs as uid 1500 with `/sandbox` as home and `/sandbox/work` as the working directory. `TOKN_OPENSHELL=1` tells TOKN where it is. `TOKN_NO_UPDATE_CHECK=1` and `TOKN_NO_REGISTER=1` stop calls the policy would block anyway.

If you use http MCP servers, `policy` adds them automatically; pass `--no-mcp` to leave them out. To allow one more host, add `--allow host:443`.

## 4. Preview, then launch

```bash
tokn openshell up --binary ./tokn_linux_amd64 --dry-run
```

The dry run prints every `openshell` and `docker` command it would run, in order, and writes nothing. When it looks right:

```bash
tokn openshell up --binary ./tokn_linux_amd64
```

`up` writes the artifacts to `.tokn-openshell/`, builds the image, imports the profile, creates the provider with `--from-existing` and creates a sandbox named `tokn`. Pass `--image` instead of `--binary` to use an image you built yourself, and `--engine podman` if your gateway uses Podman.

`--env` forwards only non-secret settings. A name ending in `_API_KEY`, `_KEY`, `_TOKEN`, `_SECRET` or `PASSWORD` is rejected:

```bash
tokn openshell up --dry-run --env MY_API_KEY=x   # refused, by design
```

## 5. Use the sandbox

```bash
tokn openshell exec --name tokn -- doctor
tokn openshell exec --name tokn -- agent-run --prompt "List the files in /sandbox/work and summarise them"
```

`doctor` shows an OpenShell section that lists the placeholder names, never their values. Now ask the agent to fetch a site that is not in the policy:

```bash
tokn openshell exec --name tokn -- agent-run --prompt "Fetch https://example.org and tell me its title"
```

The request is denied by OpenShell. TOKN's in-sandbox guidance tells the model that a denied host is a policy decision. It reports the denial instead of trying another route. To permit the host, widen the policy deliberately with `--allow example.org:443` and recreate the sandbox.

## 6. Upgrading

Inside the sandbox, `tokn update` refuses to run (`--check` and `--list` still work). OpenShell pins binaries by hash, so the image is the unit of upgrade. Download a newer Linux binary, then run `tokn openshell up` again.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `preflight` reports no gateway | The OpenShell gateway is not running | Start it as described in OpenShell's docs, then rerun `preflight`. |
| Model calls fail with 401 inside the sandbox | The key was not in the host environment when the provider was created | Export it on the host, delete the provider, and rerun `up`. |
| `up` on Windows or macOS asks for `--binary` | The image needs a Linux build | Pass `--binary ./tokn_linux_amd64`, or `--image`. |
| Image not found with Podman | Podman gateways need the `localhost/` prefix | Pass `--engine podman`; TOKN adds the prefix. |
| Local Ollama unreachable | `localhost` inside the sandbox is the sandbox | TOKN rewrites a loopback `OLLAMA_BASE_URL` to `host.openshell.internal`; also allow that host in the policy. |
| Azure Entra / `az login` auth fails | The Azure CLI is not available in the sandbox | Use an API-key provider inside OpenShell. |

Run `tokn openshell explain` or `/learn openshell` for more detail.
